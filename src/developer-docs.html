مستندات یکپارچه‌سازی شریک فان‌لندز

این راهنما برای تیم فنی اپ‌هاییه که بازی‌های فان‌لندز رو داخل محصول خودشون نشون میدن. هر چیزی که برای ورود کاربر، گرفتن رویدادها و گرفتن گزارش لازم دارید همین‌جاست، همراه با نمونه‌کد آماده کپی برای ده پشته.

1معرفی

کاربری که توی اپ شما وارد شده، بدون فرم ثبت‌نام و رمز تازه وارد بازی فان‌لندز میشه. شما هویتش رو با یک توکن کوتاه‌عمر که روی سرور خودتون امضا کردید به فان‌لندز معرفی می‌کنید. فان‌لندز امضا رو با کلید عمومی شما چک می‌کنه، بازیکن رو پیدا می‌کنه یا می‌سازه و نشست بازی رو باز می‌کنه.

نمایش بازی در اپ شما

بازی داخل یک iframe توی صفحه شما اجرا میشه. نسخه اول برای وبه و اپ موبایل و TV مسیر جدایی لازم دارن که هنوز منتشر نشده.

ورود یکپارچه با launch امضاشده

سرور شما یک JWT با typ مخصوص امضا می‌کنه و صفحه اون رو با یک فرم به فان‌لندز می‌فرسته. توکن هیچ‌وقت توی URL نمیره.

رویدادها و Webhook

شروع نشست، پایان بازی، حذف حساب و بقیه رویدادهای بازیکن به‌شکل SET امضاشده به نشانی ثبت‌شده شما می‌رسن. اگه چیزی جا موند، از API بازیابی می‌گیریدش.

API گزارش‌ها

آمار روزانه، آمار هر بازی و فعالیت هر بازیکن خودتون رو با یک توکن سرور به سرور می‌خونید. هر پاسخ زمان ساخت و تاخیر داده رو هم میگه.

مدل اعتماد

هر طرف با کلید خصوصی خودش امضا می‌کنه و کلیدهای عمومیش رو توی یک JWKS روی HTTPS منتشر می‌کنه. طرف مقابل کلید رو فقط از نشانی‌ای می‌خونه که موقع ثبت اعلام شده. هیچ کلید خصوصی، رمز مشترک یا کلید HMAC بین دو طرف جابه‌جا نمیشه.

محیط‌ها و نشانی‌ها

دو محیط داریم: sandbox برای توسعه و تست با داده غیرواقعی، و production برای کاربرهای واقعی. این دو کاملا از هم جدا هستن: کلید، issuer، audience، client_id، نشانی Webhook و داده هر کدوم مستقله. توکنی که برای یک محیط امضا شده توی محیط دیگه رد میشه. یک sub یکسان توی sandbox و production دو بازیکن جدا در فان‌لندزه و داده بازی و گزارش‌هاشون هیچ‌وقت قاطی نمیشه.

دادهآزمایشی، بدون اطلاعات کاربر واقعیواقعی

نشانی‌های فان‌لندز توی این صفحه همون نشانی‌های واقعی هستن: sandbox روی sandbox-api.funlands.ir و sandbox-play.funlands.ir، و production روی api.funlands.ir و play.funlands.ir. دامنه‌هایی مثل partner.example مال یک شریک فرضی‌ان و کلیدها، client_idها و scopeهای نمونه‌کدها نمونه‌ان. کلیدها، client_id، scopeها و سه audience (launch، خروج و token endpoint) هر محیط توی برگ شریک میان. همون مقدارها رو عینا بذارید. این سه audience با هم فرق دارن تا توکن یک نوع هیچ‌وقت به‌جای نوع دیگه قبول نشه. مقایسه audience حرف‌به‌حرفه و یک / اضافه در انتها هم توکن رو رد می‌کنه. issuer فان‌لندز همون نشانی پایه‌ایه که این audienceها روش ساخته شدن، یعنی token endpoint بدون /oauth/token.

دو مقدار جدا دارید. نشانی پایه API (FUNLANDS_BASE) برای JWKS فان‌لندز، /oauth/token، API گزارش، feed رویداد و خروج سرور به سرور به کار میره. Origin بازی (FUNLANDS_GAME_ORIGIN) جاییه که صفحه handoff و صفحه بازی روش باز میشن: فرم launch به همین Origin میره، bootstrap فقط درخواستی رو قبول می‌کنه که Originش دقیقا همین مقدار باشه، و frame-src، form-action و چک postMessage صفحه شما هم باید همین مقدار رو داشته باشن. توی بعضی استقرارها این دو یکی هستن، ولی همیشه مقدار برگ شریک رو بذارید.

نسخه‌بندی

  • نسخه توی مسیر میاد: /v1/... برای ورود و نشست، و /partner/v1/... برای APIهای سرور به سرور.
  • تا وقتی v1 هست فقط تغییرهای سازگار منتشر میشن: فیلد اختیاری تازه در پاسخ، نوع رویداد تازه و کد خطای تازه. کد شما باید فیلد ناشناخته رو نادیده بگیره، رویداد ناشناخته رو ذخیره کنه و باز هم 202 برگردونه، و با کد خطای ناشناخته مثل یک خطای عمومی رفتار کنه.
  • تغییر ناسازگار فقط با نسخه تازه مسیر (v2) میاد. قبلش خبر میدیم و تا آخر دوره گذار هر دو نسخه کار می‌کنن.
  • هر رویداد schema_version داره و هر پاسخ گزارش metric_definition_version. اگه روش محاسبه یک شاخص عوض بشه این عدد بالا میره، پس عددهای دو نسخه مختلف رو مستقیم با هم مقایسه نکنید.

2شروع سریع

این پنج قدم رو به ترتیب توی sandbox انجام بدید. هر قدم به بخش کامل خودش لینک داره.

  1. کلید بسازیدیک جفت‌کلید ES256 (منحنی P-256) برای امضای launch و خروج بسازید، و بهتره یک جفت دیگه هم برای API گزارش. کلید خصوصی توی KMS یا HSM شما می‌مونه و بیرون نمیاد. الزامات کلید
  2. JWKS رو منتشر کنیدکلیدهای عمومی رو روی نشانی‌ای مثل https://partner.example/.well-known/jwks.json منتشر کنید، فقط با فیلدهای عمومی و بدون d، p یا q. انتشار JWKS
  3. توی فان‌لندز ثبت بشیدبرگ شریک رو برای هر محیط بفرستید: issuer، نشانی JWKS، Originهای وب، نشانی Webhook، قالب sub، منطقه زمانی و راه تماس اضطراری. در جواب partner_id، client_id، scopeها، audienceها، نشانی JWKS فان‌لندز و Origin بازی رو می‌گیرید.
  4. launch رو پیاده کنیدسرور شما برای هر ورود یک verifier تازه می‌سازه، توکن launch رو امضا می‌کنه و صفحه‌ای برمی‌گردونه که فرم رو خودکار داخل iframe می‌فرسته. ورود بازیکن
  5. Webhook رو راه بندازیدیک endpoint بسازید که SET رو چک کنه، رویداد رو با کلید event_id ماندگار ذخیره کنه و تا ۵ ثانیه 202 بده. رویدادها

3کلیدها و JWKS

الزامات کلید

  • برای هر محیط یک الگوریتم ثبت میشه و فان‌لندز فقط همون رو قبول می‌کنه، نه الگوریتمی که توی هدر توکن اومده. پیشنهاد ما ES256 هست. RS256 و PS256 هم با کلید RSA دست‌کم ۲۰۴۸ بیتی قبول میشن. none و کل خانواده HS* همیشه رد میشن.
  • هر کلید یک kid غیرخالی داره که توی issuer و محیط شما یکتاست. kid کلیدی که بازنشسته شده رو هیچ‌وقت برای کلید تازه استفاده نکنید. قالب پیشنهادی: <name>-<env>-<yyyy-mm>، مثلا partner-sandbox-2026-11.
  • هر کلید تازه رو دست‌کم ۲۴ ساعت قبل از اولین امضا توی JWKS منتشر کنید و هر کلید بازنشسته رو دست‌کم ۲۴ ساعت بعد از آخرین امضا توی JWKS نگه دارید.
  • کلید خصوصی توی KMS یا HSM شما ساخته و نگه داشته میشه. نمونه‌کدها برای ساده بودن فایل PEM می‌خونن. توی production امضا رو به KMS بسپارید.
  • کلیدهای sandbox و production جدا هستن. برای API گزارش کلید جدا با kid جدا داشته باشید تا لو رفتن یکی روی اون یکی اثر نذاره.
  • هدرهای jku، x5u، jwk، x5c و crit رو توی توکن نذارید. فان‌لندز کلید رو فقط از نشانی ثبت‌شده می‌خونه و توکنی که این هدرها رو داره با TOKEN_TYPE_INVALID رد میشه.

انتشار JWKS شما

JWKS یک سند JSON عمومیه، به این شکل:

JSON
{
  "keys": [
    {
      "kty": "EC",
      "crv": "P-256",
      "x": "<base64url-x-coordinate-43-chars>",
      "y": "<base64url-y-coordinate-43-chars>",
      "kid": "partner-sandbox-2026-11",
      "alg": "ES256",
      "use": "sig"
    }
  ]
}

فان‌لندز JWKS شما رو این‌طوری می‌خونه:

  • فقط نشانی ثبت‌شده، فقط HTTPS و بدون دنبال کردن ریدایرکت. نشانی باید به IP عمومی برسه و نشانی‌های داخلی، loopback و link-local رد میشن.
  • timeout سه ثانیه‌ست، پاسخ حداکثر ۶۴ کیلوبایت و حداکثر ۲۰ کلید.
  • نتیجه ۵ دقیقه کش میشه. اگه kid توکن توی کش نباشه، JWKS یک بار دیگه خونده میشه (برای هر محیط حداکثر یک بار در هر ۳۰ ثانیه) و اگه باز هم نبود، توکن با KEY_NOT_FOUND رد میشه.
  • اگه JWKS شما در دسترس نباشه، فقط کلیدهایی که قبلا معتبر و توی کش بودن تا حداکثر یک ساعت استفاده میشن. کلید ناشناخته توی این حالت هیچ‌وقت قبول نمیشه.

import { writeFile } from 'node:fs/promises';

  await writeFile(`keys/${kid}.pub.pem`, await exportSPKI(publicKey));
}

  • حداکثر ۵ دقیقه کش کنید (طبق Cache-Control). اگه kid ناشناخته دیدید یک بار دوباره بخونید، با دست‌کم ۳۰ ثانیه فاصله بین دو بار.
  • نشانی JWKS رو از برگ شریک بگیرید و توی تنظیمات خودتون ثابت نگه دارید. نشانی کلید رو هیچ‌وقت از هدر توکن نخونید.
  • فان‌لندز هم کلید تازه رو دست‌کم ۲۴ ساعت قبل از استفاده منتشر می‌کنه و کلید قدیمی رو دست‌کم ۲۴ ساعت بعد از آخرین امضا نگه می‌داره.

چرخش برنامه‌ریزی‌شده کلید

  1. آماده‌سازیکلید تازه K2 رو با kid تازه توی KMS بسازید و هنوز با K1 امضا کنید.
  2. انتشار قبل از استفادهK1 و K2 رو با هم توی JWKS منتشر کنید و دست‌کم ۲۴ ساعت صبر کنید.
  3. عوض کردن کلید امضااز این به بعد با K2 امضا کنید. فان‌لندز کلید درست رو با kid پیدا می‌کنه.
  4. پایان هم‌پوشانیK1 رو دست‌کم ۲۴ ساعت بعد از آخرین امضا توی JWKS نگه دارید، بعد حذفش کنید و توی KMS غیرفعالش کنید.

عوض کردن الگوریتم (مثلا از ES256 به RS256) چرخش کلید حساب نمیشه. این تغییر تنظیمات ثبته و باید جدا هماهنگ و روی sandbox تست بشه.

ابطال اضطراری کلید

اگه فکر می‌کنید کلید خصوصیتون لو رفته، منتظر چرخش عادی نمونید:

  1. توقف امضاامضا با کلید لو رفته رو همین الان متوقف کنید و کلید رو توی KMS غیرفعال کنید.
  2. کلید جایگزینکلید تازه با kid تازه بسازید و منتشر کنید. اینجا منتظر مهلت ۲۴ ساعته نمونید، چون فان‌لندز با دیدن kid ناشناخته JWKS رو دوباره می‌خونه.
  3. خبر دادن به فان‌لندزاز کانال امنیتی ثبت‌شده (تماس اضطراری برگ شریک) خبر بدید: issuer، محیط، kid لو رفته و زمان تقریبی. این پیام نباید با کلید لو رفته امضا شده باشه.
  4. ابطال در فان‌لندزفان‌لندز جفت issuer و kid رو برای اون محیط توی denylist می‌ذاره. denylist قبل از کش چک میشه، پس از همون لحظه هر توکن با اون kid، حتی با exp معتبر، با KEY_NOT_FOUND رد میشه. نشست‌هایی که با اون کلید باز شدن هم طبق روال حادثه بسته میشن.

فقط حذف کلید از JWKS کافی نیست، چون نسخه کش‌شده تا چند دقیقه معتبر می‌مونه. مرحله خبر دادن رو هم همیشه انجام بدید.

اگه کلید فان‌لندز لو بره، همین روال برعکس اجرا میشه: از کانال ثبت‌شده بهتون خبر میدیم، شما kid لو رفته رو توی سیستم خودتون رد کنید، و بعد از رفع مشکل رویدادها با امضای تازه و همون event_id دوباره فرستاده میشن.

4ورود بازیکن (Launch)

ورود وب چهار مرحله داره. فقط دو مرحله اول کار شماست و دو مرحله بعد رو صفحه‌های فان‌لندز انجام میدن.

  1. سرور شما بعد از احراز هویت کاربر یک bootstrap_verifier تصادفی می‌سازه و توکن launch رو با launch_challenge همون verifier امضا می‌کنه.
  2. صفحه شما یک فرم با launch_token، game و bootstrap_verifier رو داخل iframe به POST /v1/partner/launch روی Origin بازی (FUNLANDS_GAME_ORIGIN) می‌فرسته.
  3. فان‌لندز توکن رو چک می‌کنه، بازیکن و نشست رو می‌سازه و توی iframe یک صفحه HTML با یک کد یک‌بارمصرف ۳۰ ثانیه‌ای برمی‌گردونه.
  4. همون صفحه کد و verifier رو روی همون Origin به POST /v1/session/bootstrap می‌فرسته، توکن‌ها رو به صفحه بازی همین Origin میده و اون رو باز می‌کنه. صفحه بازی توکن‌ها رو فقط توی حافظه نگه می‌داره و از این به بعد فقط با access token کار می‌کنه.

verifier و challenge

این دو مقدار کد bootstrap رو به همون پنجره‌ای گره می‌زنن که فرم رو فرستاده. اگه کد از جایی مثل لاگ یا هدر Referer بیرون بره، بدون verifier به درد نمی‌خوره.

Pseudo
bootstrap_verifier = base64url(random_bytes(32))              # 43 chars, no "=" padding
launch_challenge   = base64url(SHA-256(ascii(bootstrap_verifier)))

# example
bootstrap_verifier = dBjftJeZ4CVP-mB92K27uhbUJU1p1r_wW1gFWFOEjXk
launch_challenge   = E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM
  • برای هر launch یک verifier تازه بسازید: ۳۲ بایت تصادفی امن، با base64url و بدون =.
  • challenge رو از بایت‌های ASCII خود رشته verifier حساب کنید، نه از ۳۲ بایت خام.
  • verifier رو لاگ نکنید و توی هیچ URLی نذارید. جاش فقط فیلد مخفی فرمه.
  • اگه SHA-256(bootstrap_verifier) با launch_challenge نخونه، خطای CLAIMS_INVALID می‌گیرید.

  • بدنه application/x-www-form-urlencoded هست با سه فیلد launch_token، game و bootstrap_verifier. توکن هیچ‌وقت توی query string یا fragment نمیاد.
  • فرم رو به Origin بازی بفرستید، نه به نشانی پایه API. صفحه handoff کد رو روی همون Origin با bootstrap عوض می‌کنه و bootstrap فقط Originی رو قبول می‌کنه که دقیقا برابر Origin بازی باشه. فرمی که به Origin دیگه‌ای بره به funlands:launch_failed با کد ORIGIN_NOT_ALLOWED می‌رسه.
  • هدر Originی که مرورگر می‌فرسته باید دقیقا یکی از Originهای ثبت‌شده شما باشه. درخواست بدون Origin یا با Origin: null با ORIGIN_NOT_ALLOWED رد میشه.
  • پاسخ موفق یک صفحه HTML هست که داخل iframe باز میشه، با Cache-Control: no-store، Referrer-Policy: same-origin و frame-ancestors محدود به Originهای ثبت‌شده شما. کار bootstrap رو همین صفحه انجام میده.
  • CSP صفحه خودتون رو طوری بذارید که frame-src و form-action فقط Origin بازی فان‌لندز رو مجاز کنن. صفحه‌ای که توکن رو داره با Cache-Control: no-store و Referrer-Policy: strict-origin-when-cross-origin برگردونید.
  • بار اولی که یک sub وارد میشه، بازیکن تازه ساخته میشه. ورودهای بعدی با همون sub توی همون محیط به همون بازیکن می‌رسن، حتی اگه دو ورود هم‌زمان باشن. همون sub توی محیط دیگه بازیکن جداییه. فان‌لندز بازیکن رو خودکار به حساب دیگه‌ای در فان‌لندز یا به بازیکن شریک دیگه وصل نمی‌کنه.

روی صفحه‌ای که فرم launch رو می‌فرسته Referrer-Policy: no-referrer نذارید. با این مقدار مرورگر توی POST بین دو دامنه هدر Origin: null می‌فرسته و ورود با ORIGIN_NOT_ALLOWED رد میشه. strict-origin-when-cross-origin رو بذارید (پیش‌فرض مرورگرها)، همون مقداری که نمونه‌های زیر می‌ذارن.

type PrivateKey = Awaited<ReturnType<typeof importPKCS8>>;

@Injectable()
export class LaunchTokenService implements OnModuleInit {
  private privateKey!: PrivateKey;

  async onModuleInit() {
    // Production: sign through your KMS/HSM instead of a PEM file.
    this.privateKey = await importPKCS8(await readFile(`keys/${LAUNCH_KID}.pem`, 'utf8'), 'ES256');

    return this.privateKey;     // also signs logout tokens

    const verifier = randomBytes(32).toString('base64url');

      .setSubject(input.subject)
      .setIssuedAt(now)
      .setExpirationTime(now + 120)
      .setJti(randomUUID())
      .sign(this.privateKey);

    return { token, verifier };
  }
}

def play(request, game: str):
    if not re.fullmatch(r"[a-z0-9-]{1,64}", game):
        return HttpResponseBadRequest()
    sid = request.session.setdefault("funlands_sid", str(uuid.uuid4()))
    token, verifier = mint_launch(request.user.funlands_subject, sid, game)
    nonce = secrets.token_urlsafe(16)
    response = render(request, "partner/launch.html", {
        "action": f"{FUNLANDS_GAME_ORIGIN}/v1/partner/launch",
        "token": token, "verifier": verifier, "game": game, "nonce": nonce,
    })
    response["Cache-Control"] = "no-store"
    response["Referrer-Policy"] = "strict-origin-when-cross-origin"
    response["Content-Security-Policy"] = (
        f"frame-src {FUNLANDS_GAME_ORIGIN}; form-action {FUNLANDS_GAME_ORIGIN}; "
        f"script-src 'nonce-{nonce}'; object-src 'none'; base-uri 'none'")
    return response

final class LaunchToken
{
    /** @return array{0: string, 1: string} [token, verifier] */
    public static function mint(string $subject, string $sid, string $game): array
    {
        $verifier = self::b64url(random_bytes(32));
        $challenge = self::b64url(hash('sha256', $verifier, true));
        $now = time();
        $kid = config('funlands.launch_kid');

        $claims = [
            'iss' => config('funlands.issuer'),
            'aud' => config('funlands.launch_audience'),
            'sub' => $subject,
            'sid' => $sid,
            'iat' => $now,
            'exp' => $now + 120,
            'jti' => (string) Str::uuid(),
            'game' => $game,
            'launch_challenge' => $challenge,
            'locale' => 'fa-IR',
        ];
        $privatePem = file_get_contents(storage_path("keys/{$kid}.pem")); // production: KMS signer
        $token = JWT::encode($claims, $privatePem, 'ES256', $kid, ['typ' => 'funlands-launch+jwt']);

        return [$token, $verifier];
    }

    public static function b64url(string $bytes): string
    {
        return rtrim(strtr(base64_encode($bytes), '+/', '-_'), '=');
    }
}

// LoadPrivateKey reads a PKCS#8 PEM key. Production: sign through your KMS/HSM.
func LoadPrivateKey(kid string) (jwk.Key, error) {
	raw, err := os.ReadFile("keys/" + kid + ".pem")
	if err != nil {
		return nil, err
	}
	key, err := jwk.ParseKey(raw, jwk.WithPEM(true))
	if err != nil {
		return nil, err
	}
	return key, key.Set(jwk.KeyIDKey, kid)
}

func randomB64(n int) string {
	b := make([]byte, n)
	if _, err := rand.Read(b); err != nil {
		panic(err)
	}
	return base64.RawURLEncoding.EncodeToString(b)
}

// SignJWT signs claims with ES256 and the exact typ header given.
func SignJWT(key jwk.Key, typ string, claims map[string]any) (string, error) {
	payload, err := json.Marshal(claims)
	if err != nil {
		return "", err
	}
	hdrs := jws.NewHeaders()
	_ = hdrs.Set(jws.TypeKey, typ)
	_ = hdrs.Set(jws.KeyIDKey, key.KeyID())
	signed, err := jws.Sign(payload, jws.WithKey(jwa.ES256, key, jws.WithProtectedHeaders(hdrs)))
	return string(signed), err
}

func MintLaunch(key jwk.Key, subject, sid, game string) (token, verifier string, err error) {
	verifier = randomB64(32)
	sum := sha256.Sum256([]byte(verifier))
	now := time.Now().Unix()
	token, err = SignJWT(key, "funlands-launch+jwt", map[string]any{
		"iss": PartnerIssuer, "aud": LaunchAudience, "sub": subject, "sid": sid,
		"iat": now, "exp": now + 120, "jti": randomB64(16),
		"game": game, "launch_challenge": base64.RawURLEncoding.EncodeToString(sum[:]), "locale": "fa-IR",
	})
	return token, verifier, err
}

// PlayHandler serves GET /play/{game}. SessionFrom is your auth middleware's accessor; it returns the
// user's stable pairwise subject and a random per-login FunlandsSID (never your session cookie value).
func PlayHandler(key jwk.Key) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		sess, ok := SessionFrom(r)
		if !ok {
			http.Error(w, "", http.StatusUnauthorized)
			return
		}
		game := r.PathValue("game")
		if !gamePattern.MatchString(game) {
			http.Error(w, "", http.StatusBadRequest)
			return
		}
		token, verifier, err := MintLaunch(key, sess.FunlandsSubject, sess.FunlandsSID, game)
		if err != nil {
			http.Error(w, "", http.StatusInternalServerError)
			return
		}
		nonce := randomB64(16)
		h := w.Header()
		h.Set("Content-Type", "text/html; charset=utf-8")
		h.Set("Cache-Control", "no-store")
		h.Set("Referrer-Policy", "strict-origin-when-cross-origin")
		h.Set("Content-Security-Policy", "frame-src "+GameOrigin+"; form-action "+GameOrigin+
			"; script-src 'nonce-"+nonce+"'; object-src 'none'; base-uri 'none'")
		_ = launchTmpl.Execute(w, map[string]string{
			"Action": GameOrigin + "/v1/partner/launch", "Token": token, "Game": game, "Verifier": verifier, "Nonce": nonce,
		})
	}
}

package com.partner.funlands;

import static com.partner.funlands.FunlandsConfig.*;

import com.nimbusds.jose.*;
import com.nimbusds.jose.crypto.ECDSASigner;
import com.nimbusds.jwt.*;
import java.nio.charset.StandardCharsets;
import java.security.*;
import java.time.Instant;
import java.util.*;
import org.springframework.stereotype.Service;

@Service
public class LaunchTokenService {
    public record Launch(String token, String verifier) {}

    private final SecureRandom random = new SecureRandom();
    private final JWSSigner signer;

    public LaunchTokenService() throws Exception {
        this.signer = new ECDSASigner(PemKeys.privateKey(LAUNCH_KID));   // production: KMS-backed signer
    }

    public Launch mint(String subject, String sid, String game) throws Exception {
        byte[] raw = new byte[32];
        random.nextBytes(raw);
        Base64.Encoder b64url = Base64.getUrlEncoder().withoutPadding();
        String verifier = b64url.encodeToString(raw);
        String challenge = b64url.encodeToString(
            MessageDigest.getInstance("SHA-256").digest(verifier.getBytes(StandardCharsets.US_ASCII)));
        Instant now = Instant.now();

        JWSHeader header = new JWSHeader.Builder(JWSAlgorithm.ES256)
            .type(new JOSEObjectType("funlands-launch+jwt")).keyID(LAUNCH_KID).build();
        JWTClaimsSet claims = new JWTClaimsSet.Builder()
            .issuer(PARTNER_ISSUER).audience(LAUNCH_AUDIENCE).subject(subject)
            .issueTime(Date.from(now)).expirationTime(Date.from(now.plusSeconds(120)))
            .jwtID(UUID.randomUUID().toString())
            .claim("sid", sid).claim("game", game).claim("launch_challenge", challenge).claim("locale", "fa-IR")
            .build();
        SignedJWT jwt = new SignedJWT(header, claims);
        jwt.sign(signer);
        return new Launch(jwt.serialize(), verifier);
    }
}

using System.Security.Cryptography;
using Microsoft.IdentityModel.JsonWebTokens;
using Microsoft.IdentityModel.Tokens;

public sealed class PartnerSigner
{
    private readonly JsonWebTokenHandler _handler = new() { SetDefaultTimesOnTokenCreation = false };

    public SigningCredentials Credentials(string kid)
    {
        var ec = ECDsa.Create();
        ec.ImportFromPem(File.ReadAllText($"keys/{kid}.pem"));
        return new SigningCredentials(new ECDsaSecurityKey(ec) { KeyId = kid }, SecurityAlgorithms.EcdsaSha256);
    }

    public string Sign(string typ, SigningCredentials credentials, string issuer, string audience,
                       int lifetimeSeconds, Dictionary<string, object> claims)
    {
        var now = DateTime.UtcNow;
        return _handler.CreateToken(new SecurityTokenDescriptor
        {
            TokenType = typ,                              // header "typ"
            Issuer = issuer,
            Audience = audience,
            IssuedAt = now,
            Expires = now.AddSeconds(lifetimeSeconds),
            Claims = claims,
            SigningCredentials = credentials,
        });
    }
}

  • هر دو کد TOKEN_EXPIRED و SESSION_REVOKED یعنی «نشست تموم شده»: صفحه بازی دیگه refresh نمی‌کنه و funlands:relaunch_requested می‌فرسته.
  • توکن‌ها توی حافظه صفحه نگه داشته میشن، نه توی localStorage. با reload صفحه از بین میرن و ورود دوباره لازم میشه.

فضای شریک در صفحه بازی

بعد از bootstrap، صفحه بازی روی هر درخواست HTTP به APIهای بازی فقط Authorization: Bearer <access_token> رو می‌فرسته و روی هر اتصال WebSocket همین توکن رو با auth.token در handshake میده. هیچ کلید شریکی لازم نیست: access token بازیکن شریک، شریک خودش رو با خودش داره و فان‌لندز فضای شریک رو از توکن تاییدشده می‌خونه. refresh هم هدر شریک نمی‌خواد.

  • اگه درخواست یا handshakeی که توکن داره کلید شریک هم داشته باشه، اون کلید باید مال همون شریکی باشه که توکن براش صادر شده، وگرنه جواب 403 PARTNER_TOKEN_MISMATCH هست. توکن پلتفرم، یعنی توکنی که مال هیچ شریکی نیست، همراه کلید شریک همین جواب رو می‌گیره. کلید ناشناخته یا چرخیده روی هر درخواستی 401 PARTNER_KEY_INVALID می‌گیره.

// src/funlands/funlands-logout.service.ts
import { Injectable, Logger } from '@nestjs/common';
import { SignJWT } from 'jose';
import { randomUUID } from 'node:crypto';
import { FUNLANDS_BASE, LAUNCH_KID, PARTNER_ISSUER } from './funlands.config';
import { LaunchTokenService } from './launch-token.service';

const LOGOUT_AUDIENCE = `${FUNLANDS_BASE}/partner-logout`;
const BACKCHANNEL_LOGOUT_EVENT = 'http://schemas.openid.net/event/backchannel-logout';

@Injectable()
export class FunlandsLogoutService {
  private readonly logger = new Logger(FunlandsLogoutService.name);

  constructor(private readonly launch: LaunchTokenService) {}   // reuses the loaded signing key

  async send(subject: string, sid: string): Promise<void> {
    const now = Math.floor(Date.now() / 1000);
    const logoutToken = await new SignJWT({ sid, events: { [BACKCHANNEL_LOGOUT_EVENT]: {} } })
      .setProtectedHeader({ alg: 'ES256', typ: 'logout+jwt', kid: LAUNCH_KID })
      .setIssuer(PARTNER_ISSUER)
      .setAudience(LOGOUT_AUDIENCE)
      .setSubject(subject)
      .setIssuedAt(now)
      .setExpirationTime(now + 120)
      .setJti(randomUUID())
      .sign(this.launch.signingKey());

    const res = await fetch(`${FUNLANDS_BASE}/partner/v1/backchannel-logout`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({ logout_token: logoutToken }),
      signal: AbortSignal.timeout(5000),
    });
    if (res.status !== 200) {
      // 200 = executed or already executed. Otherwise queue a retry with a NEW token (new jti, iat, exp).
      this.logger.warn(`back-channel logout failed: ${res.status}`);
      throw new Error(`backchannel-logout ${res.status}`);
    }
  }
}

حذف حساب

وقتی کاربری حسابش رو توی اپ شما حذف می‌کنه، داده‌هاش در فان‌لندز هم باید حذف بشه. قاعده‌های این کار:

  • درخواست حذف با یک request_id پایدار، sub و زمان درخواست ثبت میشه. ثبت دوباره همون request_id درخواست دوم نمی‌سازه.
  • بلافاصله بعد از ثبت، همه نشست‌های اون بازیکن بسته میشن.
  • بعد پیوند هویت و داده شخصی طبق قرارداد داده حذف یا ناشناس میشه. فقط یک رکورد حداقلی برای جلوگیری از پردازش تکراری و تایید پایان کار می‌مونه. آمارهای تجمیعی که واقعا شخصی نیستن ممکنه طبق توافق بمونن.
  • «دریافت شد» و «حذف کامل شد» دو وضعیت جدا هستن. رویداد player.deleted فقط بعد از کامل شدن حذف براتون فرستاده میشه، نه موقع دریافت درخواست.
  • endpoint ثبت درخواست حذف و مهلت پایان کار توی قرارداد داده تعیین میشه و بعد از امضای اون توی همین صفحه منتشر میشه. تا اون موقع درخواست حذف از کانالی که توی قرارداد اومده فرستاده میشه و خروج (بالا) رو هم هم‌زمان بفرستید.
  • player.deleted همین الان هم فرستاده میشه، هر وقت حذف حساب یکی از بازیکن‌های شما در فان‌لندز کامل بشه. چون این حذف از درخواست شما نیومده، request_id این رویداد فعلا همیشه null هست.

چک کردن و ذخیره رویداد

  1. نوع محتوا باید application/secevent+jwt باشه و بدنه حداکثر ۶۴ کیلوبایت. بدنه رو به‌شکل متن خام بخونید، نه JSON.
  2. توی هدر: typ برابر secevent+jwt، alg برابر ES256 و kid موجود باشه، و هیچ‌کدوم از jku، x5u، jwk، x5c و crit نباشه.
  3. کلید رو با kid از JWKS فان‌لندز بردارید (کش ۵ دقیقه‌ای و یک بار خوندن دوباره برای kid ناشناخته).
  4. امضا رو چک کنید، و اینکه iss برابر issuer فان‌لندز توی همین محیط و aud برابر issuer خودتون (set_audience) باشه. این دو مقدار رو از تنظیمات خودتون بخونید، نه از درخواست.
  5. iat قدیمی‌تر از ۵ دقیقه یا بیشتر از ۳۰ ثانیه در آینده رو رد کنید.
  6. هر ورودی events رو با کلید یکتای event_id توی یک تراکنش ذخیره کنید. event_id تکراری خطا نیست: نادیده‌اش بگیرید و جواب موفق بدید.
  7. بعد از commit جواب 202 بدید و پردازش رو بعدا و جدا از روی جدول انجام بدید. جواب موفقی که فقط توی حافظه یا یک صف غیرماندگار ثبت شده قابل قبول نیست.

import { Injectable } from '@nestjs/common';
import { createRemoteJWKSet, decodeProtectedHeader, jwtVerify } from 'jose';

const FUNLANDS_ISSUER = 'https://sandbox-api.funlands.ir';                     // production: https://api.funlands.ir
const FUNLANDS_JWKS = new URL('https://sandbox-api.funlands.ir/.well-known/jwks.json');
const SET_AUDIENCE = 'https://partner.example';                                // set_audience: your own issuer
const FORBIDDEN_HEADERS = ['jku', 'x5u', 'jwk', 'x5c', 'crit'];

export interface FunlandsEvent {
  type: string;                    // full event type URI
  event_id: string;
  schema_version: number;
  player_seq: number;
  occurred_at: string;
  subject: { format: 'iss_sub'; iss: string; sub: string };
  [field: string]: unknown;
}

export class SetRejected extends Error {}

@Injectable()
export class FunlandsSetVerifier {
  // Caches keys; an unknown kid triggers one refetch, at most once per 30 s.
  private readonly jwks = createRemoteJWKSet(FUNLANDS_JWKS, {
    timeoutDuration: 3000, cooldownDuration: 30_000, cacheMaxAge: 300_000,
  });

  async verify(token: string): Promise<FunlandsEvent[]> {
    let header: ReturnType<typeof decodeProtectedHeader>;
    try {
      header = decodeProtectedHeader(token);
    } catch {
      throw new SetRejected('malformed token');
    }
    if (header.typ !== 'secevent+jwt' || header.alg !== 'ES256' || !header.kid ||
        FORBIDDEN_HEADERS.some((name) => name in header)) {
      throw new SetRejected('unexpected header');
    }
    const { payload } = await jwtVerify(token, this.jwks, {
      algorithms: ['ES256'],
      typ: 'secevent+jwt',
      issuer: FUNLANDS_ISSUER,
      audience: SET_AUDIENCE,
      clockTolerance: 30,
      maxTokenAge: '5m',            // rejects iat older than 5 min or in the future
      requiredClaims: ['iat', 'jti', 'events'],
    });
    const events = payload.events as Record<string, Omit<FunlandsEvent, 'type'>>;
    return Object.entries(events).map(([type, body]) => ({ ...body, type }));
  }
}

import type { Pool } from 'pg';
import type { FunlandsEvent } from './funlands-set.verifier';

export const PG_POOL = Symbol('PG_POOL');

@Injectable()
export class FunlandsInbox {
  constructor(@Inject(PG_POOL) private readonly pool: Pool) {}

  // Durable and idempotent: a repeated event_id is a no-op, not an error.
  async storeOnce(events: FunlandsEvent[]) {
    const client = await this.pool.connect();
    try {
      await client.query('BEGIN');
      for (const e of events) {
        await client.query(
          `INSERT INTO funlands_inbox (event_id, type, player_seq, payload)
           VALUES ($1, $2, $3, $4) ON CONFLICT (event_id) DO NOTHING`,
          [e.event_id, e.type, e.player_seq ?? null, e],
        );
      }
      await client.query('COMMIT');
    } catch (err) {
      await client.query('ROLLBACK');
      throw err;
    } finally {
      client.release();
    }
  }
}

  @HttpCode(202)
  async receive(@Headers('content-type') contentType: string | undefined, @Body() body: unknown) {

      throw new UnsupportedMediaTypeException();
    }

    try {
      events = await this.verifier.verify(body.trim());
    } catch (err) {
      const rejected = err instanceof SetRejected ||
        (err instanceof errors.JOSEError && !(err instanceof errors.JWKSTimeout));

      throw rejected ? new UnauthorizedException() : new ServiceUnavailableException();
    }
    await this.inbox.storeOnce(events);   // answer 202 only after the commit; process asynchronously
  }

import jwt
from jwt import PyJWKClient
from jwt.exceptions import PyJWKClientConnectionError

FUNLANDS_ISSUER = "https://sandbox-api.funlands.ir"                  # production: https://api.funlands.ir

# Caches the key set for 5 min and refetches once on an unknown kid.
# PyJWKClient has no refetch cooldown: rate-limit this endpoint at your proxy.
jwks_client = PyJWKClient(FUNLANDS_JWKS, cache_jwk_set=True, lifespan=300, timeout=3)


class SetRejected(Exception):
    pass


def verify_set(token: str) -> list[dict]:
    try:
        header = jwt.get_unverified_header(token)
    except jwt.PyJWTError as exc:
        raise SetRejected("malformed token") from exc
    if (header.get("typ") != "secevent+jwt" or header.get("alg") != "ES256"
            or not header.get("kid") or FORBIDDEN_HEADERS & header.keys()):
        raise SetRejected("unexpected header")
    try:
        signing_key = jwks_client.get_signing_key_from_jwt(token)
        claims = jwt.decode(token, signing_key.key, algorithms=["ES256"], audience=SET_AUDIENCE,
                            issuer=FUNLANDS_ISSUER, leeway=30,
                            options={"require": ["iat", "jti", "events"]})
    except PyJWKClientConnectionError:
        raise                                         # infrastructure problem -> 503
    except jwt.PyJWTError as exc:
        raise SetRejected(str(exc)) from exc
    now = time.time()
    if not (now - 300 - 30 <= claims["iat"] <= now + 30):   # no older than 5 min, no future iat
        raise SetRejected("stale or future iat")
    return [{**body, "type": event_type} for event_type, body in claims["events"].items()]

final class FunlandsSetVerifier
{
    private const ISSUER = 'https://sandbox-api.funlands.ir';                  // production: https://api.funlands.ir
    private const JWKS_URL = 'https://sandbox-api.funlands.ir/.well-known/jwks.json';
    private const AUDIENCE = 'https://partner.example';
    private const FORBIDDEN_HEADERS = ['jku', 'x5u', 'jwk', 'x5c', 'crit'];

    /** @return list<array<string, mixed>> */
    public function verify(string $token): array
    {
        $parts = explode('.', $token);
        $header = count($parts) === 3 ? json_decode(JWT::urlsafeB64Decode($parts[0]), true) : null;
        if (! is_array($header) || ($header['typ'] ?? null) !== 'secevent+jwt' || ($header['alg'] ?? null) !== 'ES256'
            || empty($header['kid']) || array_intersect_key($header, array_flip(self::FORBIDDEN_HEADERS))) {
            throw new SetRejected('unexpected header');
        }

        $keys = $this->keySet(false);
        if (! isset($keys[$header['kid']])) {
            $keys = $this->keySet(true);           // unknown kid: one refetch
        }

        JWT::$leeway = 30;
        try {
            $claims = JWT::decode($token, $keys);  // signature, alg from the JWK, exp/nbf/iat bounds
        } catch (\UnexpectedValueException|\DomainException|\InvalidArgumentException $e) {
            throw new SetRejected($e->getMessage(), 0, $e);
        }
        if (($claims->iss ?? null) !== self::ISSUER || ($claims->aud ?? null) !== self::AUDIENCE
            || ! isset($claims->iat, $claims->jti, $claims->events) || $claims->iat < time() - 330) {
            throw new SetRejected('claims');
        }

        $events = [];
        foreach (json_decode(json_encode($claims->events), true) as $type => $body) {
            $events[] = $body + ['type' => $type];
        }
        return $events;
    }

    private function keySet(bool $refresh): array
    {
        // At most one forced refetch per 30 s.
        if ($refresh && Cache::add('funlands:jwks:cooldown', true, 30)) {
            Cache::forget('funlands:jwks');
        }
        $jwks = Cache::remember('funlands:jwks', 300, fn () => Http::timeout(3)->withoutRedirecting()
            ->acceptJson()->get(self::JWKS_URL)->throw()->json());

        return JWK::parseKeySet($jwks);
    }
}

var errRejected = errors.New("set rejected")

type SetVerifier struct {
	cache       *jwk.Cache
	mu          sync.Mutex
	lastRefresh time.Time
}

func NewSetVerifier(ctx context.Context) (*SetVerifier, error) {
	c := jwk.NewCache(ctx)
	noRedirect := &http.Client{Timeout: 3 * time.Second,
		CheckRedirect: func(*http.Request, []*http.Request) error { return http.ErrUseLastResponse }}
	if err := c.Register(FunlandsJWKS, jwk.WithMinRefreshInterval(5*time.Minute), jwk.WithHTTPClient(noRedirect)); err != nil {
		return nil, err
	}
	return &SetVerifier{cache: c}, nil
}

// keyFor returns the Funlands key for kid; an unknown kid causes one refetch, at most every 30 s.
func (v *SetVerifier) keyFor(ctx context.Context, kid string) (jwk.Key, error) {
	set, err := v.cache.Get(ctx, FunlandsJWKS)
	if err != nil {
		return nil, err // infrastructure: 503
	}
	if key, ok := set.LookupKeyID(kid); ok {
		return key, nil
	}
	v.mu.Lock()
	defer v.mu.Unlock()
	if time.Since(v.lastRefresh) > 30*time.Second {
		v.lastRefresh = time.Now()
		if set, err = v.cache.Refresh(ctx, FunlandsJWKS); err != nil {
			return nil, err
		}
	}
	if key, ok := set.LookupKeyID(kid); ok {
		return key, nil
	}
	return nil, errRejected
}

func (v *SetVerifier) Verify(ctx context.Context, raw []byte) ([]map[string]any, error) {
	msg, err := jws.Parse(raw)
	if err != nil || len(msg.Signatures()) != 1 {
		return nil, errRejected
	}
	h := msg.Signatures()[0].ProtectedHeaders()
	if h.Type() != "secevent+jwt" || h.Algorithm() != jwa.ES256 || h.KeyID() == "" ||
		h.JWKSetURL() != "" || h.X509URL() != "" || h.JWK() != nil || h.X509CertChain() != nil || len(h.Critical()) > 0 {
		return nil, errRejected
	}
	key, err := v.keyFor(ctx, h.KeyID())
	if err != nil {
		return nil, err
	}
	tok, err := jwt.Parse(raw, jwt.WithKey(jwa.ES256, key), jwt.WithIssuer(FunlandsIssuer),
		jwt.WithAudience(SetAudience), jwt.WithAcceptableSkew(30*time.Second),
		jwt.WithRequiredClaim("iat"), jwt.WithRequiredClaim("jti"), jwt.WithRequiredClaim("events"))
	if err != nil {
		return nil, errRejected
	}
	if age := time.Since(tok.IssuedAt()); age > 5*time.Minute+30*time.Second || age < -30*time.Second {
		return nil, errRejected
	}
	rawEvents, _ := tok.Get("events")
	eventMap, ok := rawEvents.(map[string]any)
	if !ok {
		return nil, errRejected
	}
	var out []map[string]any
	for typ, body := range eventMap {
		e, ok := body.(map[string]any)
		if !ok {
			return nil, errRejected
		}
		e["type"] = typ
		out = append(out, e)
	}
	return out, nil
}

// WebhookHandler serves POST /funlands/events. db uses the pgx stdlib driver.
func WebhookHandler(v *SetVerifier, db *sql.DB) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if mt, _, _ := mime.ParseMediaType(r.Header.Get("Content-Type")); mt != "application/secevent+jwt" {
			w.WriteHeader(http.StatusUnsupportedMediaType)
			return
		}
		body, err := io.ReadAll(http.MaxBytesReader(w, r.Body, 64<<10))
		if err != nil {
			w.WriteHeader(http.StatusRequestEntityTooLarge)
			return
		}
		events, err := v.Verify(r.Context(), []byte(strings.TrimSpace(string(body))))
		switch {
		case errors.Is(err, errRejected):
			w.WriteHeader(http.StatusUnauthorized) // Funlands pauses delivery and alerts
			return
		case err != nil:
			w.WriteHeader(http.StatusServiceUnavailable) // Funlands retries
			return
		}
		tx, err := db.BeginTx(r.Context(), nil)
		if err != nil {
			w.WriteHeader(http.StatusServiceUnavailable)
			return
		}
		defer tx.Rollback()
		for _, e := range events {
			payload, _ := json.Marshal(e)
			var seq any // JSON numbers decode as float64
			if f, ok := e["player_seq"].(float64); ok {
				seq = int64(f)
			}
			if _, err := tx.ExecContext(r.Context(),
				`INSERT INTO funlands_inbox (event_id, type, player_seq, payload)
				 VALUES ($1, $2, $3, $4) ON CONFLICT (event_id) DO NOTHING`,
				e["event_id"], e["type"], seq, payload); err != nil {
				w.WriteHeader(http.StatusServiceUnavailable)
				return
			}
		}
		if err := tx.Commit(); err != nil {
			w.WriteHeader(http.StatusServiceUnavailable)
			return
		}
		w.WriteHeader(http.StatusAccepted)
	}
}

package com.partner.funlands;

import com.nimbusds.jose.*;
import com.nimbusds.jose.jwk.source.*;
import com.nimbusds.jose.proc.*;
import com.nimbusds.jwt.*;
import com.nimbusds.jwt.proc.*;
import java.net.URL;
import java.time.Instant;
import java.util.*;
import org.springframework.stereotype.Component;

@Component
public class FunlandsSetVerifier {
    static final String ISSUER = "https://sandbox-api.funlands.ir";           // production: https://api.funlands.ir
    static final String JWKS_URL = "https://sandbox-api.funlands.ir/.well-known/jwks.json";
    static final String AUDIENCE = "https://partner.example";

    public static class SetRejected extends Exception {
        public SetRejected(String message) { super(message); }
    }

    private final ConfigurableJWTProcessor<SecurityContext> processor = new DefaultJWTProcessor<>();

    public FunlandsSetVerifier() throws Exception {
        // Default builder: 5 min cache, refetch on unknown kid, rate limited, retrying.
        JWKSource<SecurityContext> keys = JWKSourceBuilder.create(new URL(JWKS_URL)).retrying(true).build();
        processor.setJWSTypeVerifier(new DefaultJOSEObjectTypeVerifier<>(new JOSEObjectType("secevent+jwt")));
        processor.setJWSKeySelector(new JWSVerificationKeySelector<>(JWSAlgorithm.ES256, keys));
        var claims = new DefaultJWTClaimsVerifier<SecurityContext>(AUDIENCE,
            new JWTClaimsSet.Builder().issuer(ISSUER).build(), Set.of("iat", "jti", "events"));
        claims.setMaxClockSkew(30);
        processor.setJWTClaimsSetVerifier(claims);
    }

    /** Returns one map per event; throws KeySourceException when the JWKS cannot be fetched. */
    public List<Map<String, Object>> verify(String token) throws SetRejected, KeySourceException {
        try {
            JWSHeader h = JWSObject.parse(token).getHeader();
            if (h.getJWKURL() != null || h.getX509CertURL() != null || h.getJWK() != null
                || h.getX509CertChain() != null || h.getCriticalParams() != null || h.getKeyID() == null) {
                throw new SetRejected("unexpected header");
            }
            JWTClaimsSet c = processor.process(token, null);
            Instant iat = c.getIssueTime().toInstant();
            if (iat.isBefore(Instant.now().minusSeconds(330)) || iat.isAfter(Instant.now().plusSeconds(30))) {
                throw new SetRejected("stale or future iat");
            }
            List<Map<String, Object>> events = new ArrayList<>();
            for (var entry : c.getJSONObjectClaim("events").entrySet()) {
                @SuppressWarnings("unchecked")
                var body = new HashMap<>((Map<String, Object>) entry.getValue());
                body.put("type", entry.getKey());
                events.add(body);
            }
            return events;
        } catch (KeySourceException e) {
            throw e;                                   // infrastructure: 503
        } catch (java.text.ParseException | BadJOSEException | JOSEException | ClassCastException e) {
            throw new SetRejected(e.getMessage());
        }
    }
}

using System.Text;
using System.Text.Json;
using Microsoft.IdentityModel.JsonWebTokens;
using Microsoft.IdentityModel.Tokens;

public sealed class SetRejectedException(string message) : Exception(message);

public sealed class FunlandsSetVerifier(HttpClient http)
{
    private const string Issuer = "https://sandbox-api.funlands.ir";            // production: https://api.funlands.ir
    private const string JwksUrl = "https://sandbox-api.funlands.ir/.well-known/jwks.json";
    private const string Audience = "https://partner.example";
    private static readonly string[] ForbiddenHeaders = ["jku", "x5u", "jwk", "x5c", "crit"];

    private readonly JsonWebTokenHandler _handler = new();
    private readonly SemaphoreSlim _lock = new(1, 1);
    private IList<SecurityKey> _keys = [];
    private DateTime _fetchedAt = DateTime.MinValue;

    // Cache 5 min; an unknown kid forces one refetch, at most every 30 s.
    private async Task<IList<SecurityKey>> KeysAsync(bool unknownKid)
    {
        var age = DateTime.UtcNow - _fetchedAt;
        if (age < TimeSpan.FromMinutes(5) && !(unknownKid && age > TimeSpan.FromSeconds(30))) return _keys;
        await _lock.WaitAsync();
        try
        {
            var json = await http.GetStringAsync(JwksUrl);   // 3 s timeout, no redirects (see Program.cs)
            _keys = new JsonWebKeySet(json).GetSigningKeys();
            _fetchedAt = DateTime.UtcNow;
            return _keys;
        }
        finally { _lock.Release(); }
    }

    /// <exception cref="SetRejectedException">token rejected (answer 401)</exception>
    /// <exception cref="HttpRequestException">JWKS unreachable (answer 503)</exception>
    public async Task<List<Dictionary<string, JsonElement>>> VerifyAsync(string token)
    {
        JsonWebToken jwt;
        try { jwt = _handler.ReadJsonWebToken(token); }
        catch (Exception) { throw new SetRejectedException("malformed token"); }
        if (jwt.Typ != "secevent+jwt" || jwt.Alg != "ES256" || string.IsNullOrEmpty(jwt.Kid) ||
            ForbiddenHeaders.Any(name => jwt.TryGetHeaderValue<object>(name, out _)))
            throw new SetRejectedException("unexpected header");

        var keys = await KeysAsync(unknownKid: false);
        if (!keys.Any(k => k.KeyId == jwt.Kid)) keys = await KeysAsync(unknownKid: true);

        var result = await _handler.ValidateTokenAsync(token, new TokenValidationParameters
        {
            ValidIssuer = Issuer,
            ValidAudience = Audience,
            IssuerSigningKeys = keys,
            ValidAlgorithms = ["ES256"],
            ValidTypes = ["secevent+jwt"],
            RequireExpirationTime = false,               // a SET carries no exp
            ClockSkew = TimeSpan.FromSeconds(30),
        });
        if (!result.IsValid) throw new SetRejectedException(result.Exception?.Message ?? "invalid");

        var iat = jwt.IssuedAt;                          // DateTime.MinValue when absent
        if (iat < DateTime.UtcNow.AddSeconds(-330) || iat > DateTime.UtcNow.AddSeconds(30) || string.IsNullOrEmpty(jwt.Id))
            throw new SetRejectedException("iat/jti");

        using var payload = JsonDocument.Parse(Base64UrlEncoder.Decode(jwt.EncodedPayload));
        if (!payload.RootElement.TryGetProperty("events", out var events) || events.ValueKind != JsonValueKind.Object)
            throw new SetRejectedException("events");
        var list = new List<Dictionary<string, JsonElement>>();
        foreach (var e in events.EnumerateObject())
        {
            var body = e.Value.Deserialize<Dictionary<string, JsonElement>>()!;
            body["type"] = JsonSerializer.SerializeToElement(e.Name);
            list.Add(body);
        }
        return list;
    }
}

func (c *ReportsClient) accessToken() (string, error) {
	c.mu.Lock()
	defer c.mu.Unlock()
	if c.token != "" && time.Now().Before(c.expiresAt) {
		return c.token, nil
	}
	now := time.Now().Unix()
	assertion, err := SignJWT(c.key, "JWT", map[string]any{
		"iss": ClientID, "sub": ClientID, "aud": TokenEndpoint,
		"iat": now, "exp": now + 60, "jti": randomB64(16),

		"scope":                 {"reports:read"},
		"client_assertion_type": {"urn:ietf:params:oauth:client-assertion-type:jwt-bearer"},
		"client_assertion":      {assertion},
	}
	res, err := c.http.Post(TokenEndpoint, "application/x-www-form-urlencoded", strings.NewReader(form.Encode()))
	if err != nil {
		return "", err
	}
	defer res.Body.Close()
	var body struct {
		AccessToken string `json:"access_token"`
		ExpiresIn   int    `json:"expires_in"`
		Error       string `json:"error"`
	}
	if err := json.NewDecoder(res.Body).Decode(&body); err != nil {
		return "", err
	}
	if res.StatusCode != http.StatusOK {
		return "", fmt.Errorf("token endpoint %d: %s", res.StatusCode, body.Error)
	}
	c.token = body.AccessToken
	c.expiresAt = time.Now().Add(time.Duration(body.ExpiresIn-60) * time.Second)
	return c.token, nil
}

تعریف شاخص‌ها

این تعریف‌ها توی API و پنل شریک یکی هستن و با metric_definition_version نسخه‌بندی میشن. همه شمارش‌ها فقط بازیکن‌ها و فعالیت خود شما رو در بر می‌گیرن. گزارش‌ها از نشست‌های بازی فان‌لندز ساخته میشن، نه از رویدادهای Webhook: شروع هر نشست بازی یک game.started حساب میشه و نشستی که کامل تموم بشه یک game.completed. برای همین DAU و نرخ تکمیل همین الان هم عدد دارن، با اینکه رویداد Webhook game.started هنوز فرستاده نمیشه. روزها به وقت Asia/Tehran شمرده میشن.

شاخصتعریف
DAU (dau)تعداد sub یکتا که توی یک روز تقویمی به وقت Asia/Tehran دست‌کم یک نشست بازی شروع کردن (یک game.started به معنای بالا).
dau_averageمیانگین DAU روی همه روزهای بازه. روز بدون بازی صفر حساب میشه.
MAU (mau)تعداد sub یکتا با دست‌کم یک game.started توی ماه تقویمی‌ای که to توشه، محدود به بازه درخواست: از from یا روز اول اون ماه، هر کدوم دیرتر بود، تا آخر روز to.
game_starts، game_completionsتعداد نشست‌های بازی که توی بازه شروع شدن، و تعداد اون‌هایی که کامل تموم شدن.
completion_rategame_completions تقسیم بر game_starts توی همون گروه شروع (cohort). اگه شروعی نباشه null هست.
playtime_secondsاز بازه‌های نشست بازی حساب میشه، با حذف هم‌پوشانی و با سقف برای هر بازه، و به روز شروع نشست نسبت داده میشه. جمع ساده زمان‌هایی که کلاینت گزارش کرده نیست.
ماندگاری روز Nسهم بازیکن‌های گروه «اولین بازی» یک روز که N روز بعد هم game.started داشتن. توی پنل شریک نشون داده میشه و توی v1 endpoint جدا نداره.
  • رویدادهای دیررس ممکنه عددهای روزهای اخیر رو تا آخر دوره data_lag_seconds عوض کنن. برای گزارش نهایی یک روز، بعد از تموم شدن اون روز و گذشتن این تاخیر بخونید.
  • هیچ شمارنده‌ای مبنای صورتحساب نیست، مگر اینکه فرمول و روال تطبیقش جدا تعریف و امضا شده باشه.

  • برنامه چرخش کلید و مالکش مشخصه.
  • تماس اضطراری امنیتی ثبت شده و روال ابطال اضطراری یک بار تمرین شده.
  • ساعت همه سرورهای امضاکننده با NTP هماهنگه.
  • توکن launch فقط سمت سرور و فقط بعد از احراز هویت ساخته میشه و هیچ توکن، verifier یا کدی توی URL یا لاگ نیست.
  • sub مستعار و پایداره و sid شناسه‌ای جدا از کوکی نشسته.
  • Originهای production ثبت شدن، فرم launch به Origin بازی production میره و CSP صفحه شما frame-src و form-action رو به همون Origin محدود کرده.
  • صفحه بازی بعد از bootstrap فقط Authorization: Bearer (و توی WebSocket فقط auth.token) می‌فرسته، هیچ کلید یا سکرت شریکی توی صفحه بازی یا مرورگر نیست، و درخواستی که توکن داره با کلید شریک دیگه 403 PARTNER_TOKEN_MISMATCH می‌گیره.
  • ورود دوباره با postMessage و پیام خطای قابل فهم پیاده شده.
  • خروج سرور به سرور با صف تکرار پیاده شده.
  • Webhook رویداد رو ماندگار و بدون تکرار ذخیره می‌کنه، تا ۵ ثانیه جواب میده و 401 و 503 رو درست از هم جدا می‌کنه.

  • همه سناریوهای sandbox پایین با موفقیت اجرا شدن.

10سوال‌های رایج

چرا امضا با کلید مشترک (HMAC) نیست؟

هر کسی که کلید مشترک رو داشته باشه می‌تونه به‌جای هر دو طرف توکن بسازه، و چرخش و ابطالش هم هماهنگی دستی می‌خواد. با امضای نامتقارن، کلید خصوصی هیچ‌وقت از سیستم شما بیرون نمیره و ما فقط کلید عمومی رو از نشانی ثبت‌شده می‌خونیم.

کاربرهای ما با OIDC وارد میشن. می‌تونیم همون id_token رو بفرستیم؟

نه. id_token برای اپ شما صادر شده و audience و typ دیگه‌ای داره. توکن launch رو جدا با typ برابر funlands-launch+jwt بسازید. اگه واقعا لازم دارید id_token قبول بشه، این یک پروفایل جدا با audience و nonce خودشه که باید جدا توافق بشه.

اپ Android یا iOS ما WebView داره. همین روش کار می‌کنه؟

نسخه فعلی فقط برای وبه. WebView معمولا Origin قابل اعتماد نمی‌فرسته و درخواست بدون Origin رد میشه. ورود از اپ موبایل یا TV یک تحویل سرور به سرور جدا لازم داره که برای هر پلتفرم جدا تایید میشه و بعدا منتشر میشه.

ساعت سرورهای ما کمی جلو یا عقبه. مشکلی پیش میاد؟

تا ۳۰ ثانیه اختلاف قبول میشه. بیشتر از اون، توکن‌ها با TOKEN_EXPIRED رد میشن. ساعت سرورهای امضاکننده رو با NTP هماهنگ کنید.

چرا هر بار که یک رویداد دوباره فرستاده میشه jti عوض میشه؟

چون هر تلاش ارسال یک SET تازه با iat تازه‌ست. اگه همون JWT اول بعد از ۷۲ ساعت دوباره می‌اومد، گیرنده‌ای که SET قدیمی‌تر از ۵ دقیقه رو رد می‌کنه نمی‌تونست قبولش کنه. برای همین dedupe رو همیشه روی event_id انجام بدید.

Webhook ما چند ساعت از کار افتاد. رویدادها از دست رفتن؟

نه. فان‌لندز تا ۷۲ ساعت دوباره تلاش می‌کنه. اگه بیشتر طول کشید یا توی player_seq جای خالی دیدید، از GET /partner/v1/events با cursor بخونید. اگه رویدادی به dead letter رفته، replayش رو درخواست کنید.

کاربر صفحه رو reload کرد و بازی دوباره ورود خواست. طبیعیه؟

بله. توکن‌های بازی فقط توی حافظه صفحه نگه داشته میشن. صفحه بازی داخل iframe پیام funlands:relaunch_requested می‌فرسته و صفحه شما باید یک launch تازه از سرور خودتون بگیره. پیشرفت بازیکن روی سرور فان‌لندز ذخیره‌ست و از بین نمیره.

می‌تونیم شناسه کاربر خودمون رو مستقیم به‌عنوان sub بفرستیم؟

اگه اون شناسه جای دیگه‌ای هم دیده میشه (مثلا توی URLها یا سرویس‌های دیگه)، نه. برای هر کاربر یک شناسه تصادفی پایدار مخصوص فان‌لندز بسازید و نگهش دارید، یا HMAC شناسه داخلی رو با یک کلید مخفی حساب کنید. این شناسه نباید بعدا عوض بشه، چون sub تازه یعنی بازیکن تازه.

صفحه بازی برای درخواست‌هاش کلید شریک لازم داره؟

نه. بعد از bootstrap فقط access token بازیکن فرستاده میشه و شریک از خود توکن خونده میشه. این برای شریک‌های server_to_server هم درسته، پس سکرتشون هیچ‌وقت به مرورگر نمی‌رسه (فضای شریک در صفحه بازی).
